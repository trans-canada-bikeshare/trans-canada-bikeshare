# Changelog

All notable changes to this project are recorded here. The format follows
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and versions follow
[Semantic Versioning](https://semver.org/spec/v2.0.0.html).

**What a version means here.** This is not a library; nothing imports it. A
version is a state of the *published record* — the pipeline, the gates, the
committed artifacts in `src/data/generated/` and the site that renders them.
A major version therefore means a change in what the artifacts mean or how they
are computed, not a change in an API.

Every claim below is checkable against the spec files in
[`docs/features/`](docs/features/) and the merge commits named beside each
entry. The per-spec record — what was built, what its review found, what it
cost — is in those files and in `docs/current-feature.md`'s History; this file
is the summary, not the source.

## [1.0.0] — 2026-07-31

The first tagged release. Nothing in the data changed to produce it; what
changed over the three specs before it is that the record can now be checked
rather than believed.

**Where it stands.** The site is live at
[bikeshare.adnanreza.com](https://bikeshare.adnanreza.com) (deployed
2026-07-30, spec 027, `7d7607a`). The pipeline ingests every year all three
systems publish — **135,598,298 trips** — into a DuckDB star schema and
publishes fifteen small aggregates that the site reads and nothing else:

| System | Trips | Window |
| --- | --- | --- |
| Montreal — BIXI (`mtl-bixi`) | 88,197,834 | 2014-04-15 → 2026-06-30 |
| Toronto — Bike Share Toronto (`tor-bikeshare`) | 38,577,898 | 2016-06-30 → 2026-03-31 |
| Vancouver — Mobi by Rogers (`van-mobi`) | 8,822,566 | 2017-01-01 → 2026-07-01 |

(Read from `src/data/generated/meta.json` at the time of writing; it is
regenerated by every publish run, so the release provenance block carries the
values that shipped.)

**The gate battery, as of this release:** `make check` — manifest, metrics,
artifacts, report, reconciliation and data dictionary, all against the full
archive; `make check-fixture` — the whole pipeline over a synthetic archive,
offline, in about two seconds; `pytest pipeline/tests`; and
`npm test && npm run typecheck && npm run build`. CI runs the two a clean
runner can prove.

### Added — 031, open-source operations (this release)

- `CONTRIBUTING.md`, `CODE_OF_CONDUCT.md` (Contributor Covenant v2.1, fetched
  rather than recalled), `SECURITY.md` (GitHub private vulnerability
  reporting; no bounty), issue templates for bugs and for **data-quality
  reports with provenance fields**, and a PR template that names the gates.
- `docs/data-dictionary.md` — every field of every artifact, **generated** from
  the fifteen schema contracts and the completeness declaration by
  `pipeline/generate_data_dictionary.py`. It carries no timestamp, so
  `make check-dictionary` diffs it in full; a schema edited without
  regenerating fails the gate and fails a test before that.
- `pipeline/release_provenance.py` — the release block: commit, sha256 of every
  published artifact, toolchain versions read from the locks, and each system's
  data window read from `meta.json`.
- Dependabot for npm, pip and github-actions: monthly, grouped per ecosystem.
- A monthly refresh reminder workflow (first of the month, 14:00 UTC) that
  opens an issue from `.github/refresh-reminder.md` linking the runbook's
  refresh steps. `issues: write` and `contents: read`, nothing else.

### Changed — 031

- Every GitHub Action is pinned to a full commit SHA with its version beside
  it, both checkouts set `persist-credentials: false`, and both CI jobs carry
  `timeout-minutes`. Deferred here by name from spec 029's review.
- The Makefile's last two spec-011-era stub fallbacks are gone.
  `check-artifacts` and `check-manifest` ran their scripts only `if [ -f ]`,
  and printed a spec-002 message and exited 0 otherwise — so a renamed or
  deleted gate script would have reported success. Both now invoke
  unconditionally, and `pipeline/tests/test_gate_targets.py` asserts every gate
  target fails in a tree where its script is missing.

### Added — 030, analytical integrity (`21c007a`)

- One completeness declaration, `pipeline/completeness.py`: for each of the
  fifteen artifacts, which rule governs what reaches it and why, plus every
  numeric threshold the publisher admits or excludes rows by. The month rule
  had been written five times with two different boundaries, and three
  artifacts applied no rule at all with nothing recording that. Unifying it
  moved **zero months** — verified twice.
- Fifteen JSON Schema contracts (`pipeline/schemas/`), enforced at publish time
  in Python and over the committed files in vitest.
- A scan that fails the suite on any number in the publisher's own source that
  gates rows and did not come from the declaration.

### Changed — 030

- The "Forecast" section is renamed to weather scenario analysis: it estimates
  daily ridership under weather conditions with a level per observed calendar
  month, which is a within-month question, not a temporal forecast. The model
  is unchanged; the name was the thing that overstated it. Committed artifacts
  are byte-identical across the change.

### Added — 029, reproducibility (`a2ffdd1`)

- `pipeline/requirements.lock`: every distribution hash-pinned, CPython 3.11
  only, three platforms. `--require-hashes` or the install aborts.
- CI (`.github/workflows/ci.yml`): two jobs on clean GitHub-hosted runners.
- `make check-fixture` — the whole pipeline end to end over a committed
  synthetic archive with no network and no warehouse, then the real gates
  against the result. It is what makes the reproducibility claim checkable by
  someone who has never downloaded a byte.
- `make check-reconciliation` — the standing half of 028's per-file audit: the
  source-record counts are still true of the archive the manifests pin now, and
  any period whose checksum moved is recounted.

### Fixed — 029

- Extraction is transactional per system. It had been DELETE-then-load, so a
  late failure left a partially destroyed warehouse.
- `stations.json` had a non-deterministic sort — 26 stations in 13 tied groups
  swapped positions between two builds of the same warehouse, which would have
  failed `make check-artifacts` for anyone reproducing the project.
- The encoding-repair cache is keyed by source checksum rather than filename, so
  a republished file cannot be served a stale repaired copy.
- The van-mobi 2025-05 "date-order ambiguity" did not exist: the file is
  `YYYY/MM/DD` and both evidence patterns missed a four-digit year, so it parsed
  correctly for the wrong reason while the runbook reported an ambiguity.

### Fixed — 028, the trust release (`bbf65e3`)

- `docs/data-quality-report.md` published **0.0%** for Montreal's canonical
  station resolution; the warehouse says **88.9%** (78,431,689 of 88,197,834
  trips). The query joined an already-canonical id against an era-local one.
- The report sat outside every gate. `make check-report` now regenerates it and
  fails on any difference but the timestamp line.
- The funnel's duplicate count was landed-minus-everything-else, so its zero
  residual was true by construction. It is computed independently and refuses.
- `forecast.json` published `fit_basis: "no holdout"` while the same artifact
  carried the five-fold holdout figures the site quoted.
- Five 2016 Toronto rows with a null departure station, and 783,014 rows
  carrying the literal string `NULL` as a label, are re-accounted.
- Toronto's first trip printed as 2000-01-01 — a known implausible-date row
  leaking into `min()`.

### Changed — 028

- `LICENSE` is the MIT text and nothing else; every data obligation moved to
  `DATA-LICENSES.md`. GitHub had been classifying the licence as NOASSERTION
  because the file mixed the two.
- Mobi's published statement that departure and return times are **rounded to
  the nearest hour**, and that operations rebalancing trips are removed, is
  recorded and qualifies Vancouver's operational signal.

### Before 1.0.0

Specs 001–027 built the thing: the source column audit, the manifests and
downloaders, the warehouse, the metric registry, the publish step, the site,
the maps, flows, weather, membership, the operational signals and the deploy.
They shipped without tags, several of them in batched commits during an
overnight autonomous run. Rather than invent a release history that did not
happen, each is recorded where it actually is — one file per spec in
[`docs/features/`](docs/features/), and one line per merge in
`docs/current-feature.md`'s History, backfilled from `git log` rather than from
memory.

Two entries there matter more than the rest, because they are what the gates in
this release exist to prevent: the independent review of 2026-07-29, which
found 569,113 Toronto trips missing — 320,229 in a zip nested inside the annual
zip, 217,569 in an unread second worksheet, 31,315 dropped on invalid encoding
— and 8.9M Montreal rows landing on the wrong local day; and the adversarial
audit of 2026-07-30, which found Toronto's own Excel had transposed day and
month across a 2016 quarter, fabricating six months of ridership that never
happened.
